# 撞击检测、自适应 EKF 与角速度 DOB：实验基础版

工作分支：`codex/impact-adaptive-ekf-dob`，起点 `dcc6516e3a`。

这份实现完成冲击事件检测、EKF 过程噪声窗口调整和有界的角速度扰动补偿。
它不是已经验证的碰撞恢复系统，不能据此认为 160 g 无人机能够以 4 m/s 撞击后继续飞行。
没有自动扶正、平移状态重置、暂停位置控制、位置环积分管理或可信交接逻辑。
若速度估计错误，原位置控制器仍可能产生错误的姿态指令，DOB 无法解决这一问题。

## 实际控制链路

```text
选定 IMU 的 sensor_combined → 冲击窗口 → DOB 补偿许可
                                               ↓
原位置/姿态控制 → 原角速度 PID → 原偏航输出滤波 → 有界补偿 → 原控制分配
                                               ↑
                         角加速度、上一拍力矩指令、分配反馈
```

EKF 的检测器在各实例自己的**延迟 IMU 时间轴**运行；控制器检测器在选定 IMU
与当前控制时间轴运行。两个检测器共享算法，不共享异步标志，以免把当前碰撞错误地
应用到尚未到达碰撞时刻的 EKF 缓冲样本上。二者阈值分别配置，建议保持一致。

## 1. 事件检测

文件：`src/lib/collision_recovery/ImpactDetector.hpp`。

满足以下任一项触发：比力模超过阈值、角速度模超过阈值、IMU 削顶标志置位。
这里使用的是比力，静止时模值约为 9.81 m/s²；不是已减掉重力的运动加速度。
默认 35 m/s² 和 30 rad/s 仅用于开始测试，尚未根据用户机型标定。
没有强制要求“加速度超限且陀螺仪削顶”同时出现，以免漏掉基本不旋转的正面碰撞。
这只是冲击候选检测，快速机动、振动也可能误触发，需用正常飞行日志评估。

状态：Idle → Shock → Recovery → Idle。最后一次触发后的 80 ms 为 Shock，
其后 500 ms 为 Recovery；再次触发会延长窗口。持续异常保持 Shock 并禁止 DOB。
这些状态表示时间窗口，不表示姿态或估计器已恢复。事件计数不逐样本增长，禁用或落地后清零。

陀螺仪削顶标志已从 `vehicle_imu` / `sensor_combined` 传递到 `imuSample`，
并在下采样时逐轴作 OR，避免短时削顶丢失。

## 2. 自适应 EKF

入口：`src/modules/ekf2/EKF/covariance.cpp`。

- `EKF2_IMP_EN=0`：默认关闭，原有削顶与坏加速度处理继续运行。
- 开启后，只在 EKF 的 in_air 状态下触发。
- Shock 内将标称 IMU 噪声**方差**乘以 `EKF2_IMP_QMAX`，随后线性退回 1。
- 现有坏加速度/削顶方差作为下界保留，不会被降低。
- 不冻结均值传播、不删除真实冲量、不修改观测噪声 R、不放宽观测拒绝门限。
- 不会恢复传感器饱和期间丢失的数据，也不能保证错误速度立即收敛。

`EKF2_IMP_QMAX=25` 表示方差乘 25，即标准差乘 5，不能误读成标准差乘 25。
放大预测不确定性可能改变后续观测的接受与更新，因此也需要评估异常外部观测的影响。

前向 ToF 是沿光轴的一维距离，不能直接替代三维位置或速度。光流依赖姿态、距离和
特征质量；VIO 也使用 IMU，并可能在撞击时失效。因此本版保留原有观测质量判断。
若后续需要平移状态重置，应针对已经确认可信的传感器单独设计。

## 3. DOB 的模型与量纲

文件：`src/lib/collision_recovery/RateDisturbanceObserver.hpp`。

逐轴标称模型：

```text
alpha_i = B_i * lag(u_i) + d_i
estimated_disturbance_i = LPF(alpha_i / B_i - lag(u_i))
u_out_i = u_pid_i - estimated_disturbance_i  （受许可、限幅、限速约束）
```

- `alpha` 使用 `vehicle_angular_velocity.xyz_derivative`，单位 rad/s²。
- `u` 为归一化力矩指令，不是 N·m。
- `B_i` 单位为“rad/s² / 单位归一化力矩”，包含控制分配与机体的有效响应，不能直接填转动惯量。
- 三个 `B` 默认都是 0，未辨识轴不估计也不补偿。160 g 重量不足以推算它们。
- `lag` 是一阶执行器模型，时间常数为 `MC_DOB_TAU`。
- 残差包含模型误差和轴间耦合，不能解释成精确测得的碰撞力矩。

这是因果的撞后扰动估计，不能在碰撞发生前预测冲量，也不能让有限带宽的电机
抵消毫秒级接触力。过高 DOB 带宽会放大导数噪声和延迟影响。
`B`、时间常数、滤波延迟、PID 积分器和电池电压变化都需要联合评估。

补偿条件：模式为 2、普通多旋翼、已解锁且离地、Offboard、Recovery 窗口，
IMU 与角速度样本新鲜且未削顶，角加速度有限，控制分配反馈新鲜、推力与力矩均可分配，
且没有分配器报告的电机故障/停止。缺失分配反馈也禁止补偿。

持续削顶、Shock、异常时间间隔、落地和失效数据均不学习冲击残差，并立即禁止输出。
执行器模型在有效时间步内继续跟踪上一拍指令，避免恢复测量时把自身推力误认为扰动。
窗口正常结束时补偿按限速退出；故障禁用允许立即撤销补偿。

## 参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `MC_IMP_MODE` | 0 | 0 关闭；1 仅监测；2 允许实验补偿 |
| `MC_IMP_ACC` | 35 | 比力模触发阈值，m/s² |
| `MC_IMP_RATE` | 30 | 角速度模触发阈值，rad/s |
| `MC_DOB_B_R/P/Y` | 0 | 各轴归一化力矩效能，0 禁用对应轴 |
| `MC_DOB_BW` | 5 | 观测器低通带宽，Hz |
| `MC_DOB_TAU` | 0.04 | 标称执行器时间常数，s |
| `MC_DOB_LIM` | 0.1 | 各轴归一化补偿绝对上限 |
| `MC_DOB_SLEW` | 0.5 | 补偿变化速率，归一化力矩/s |
| `EKF2_IMP_EN` | 0 | EKF 过程噪声自适应开关 |
| `EKF2_IMP_ACC` | 35 | EKF 比力触发阈值，m/s² |
| `EKF2_IMP_RATE` | 30 | EKF 角速度触发阈值，rad/s |
| `EKF2_IMP_QMAX` | 25 | 标称 IMU 噪声方差最大倍率 |

模式 1 不改变控制输出；EKF 自适应是独立开关，想做纯监测应保持它为 0。

## 使用顺序

先在 SITL 使用监测模式；以下命令是 PX4 控制台命令，不是 Linux shell：

```text
param set MC_IMP_MODE 1
param set EKF2_IMP_EN 0
listener impact_recovery_status
```

先完成正常悬停日志与仿真扰动对照，再单独开启 EKF 自适应，检查
`estimator_impact_status` 中方差倍率与 EKF 创新、状态、削顶记录是否吻合。

模式 2 需要先辨识各轴 `B` 和时间常数，再在仿真、受约束台架逐级验证。
没有一套针对未知机型的可直接飞行补偿参数；本版也没有植入任何自动撞击任务。
现有 MAVSDK 起降程序可以继续作为任务层，无需把快速 DOB 放到串口往返链路中。

## 日志

- `impact_recovery_status`：控制窗口、事件计数、IMU 新鲜度、分配状态、估计扰动和实际补偿。
  `correction` 是电池缩放前加入的值，不是实际电机力矩。
- `estimator_impact_status`：各 EKF 实例的延迟时间戳、IMU 设备 ID、窗口与方差倍率。
  对照其他多实例 EKF 日志时应通过设备 ID 确认实例，不能只猜 topic 的实例编号。

两个主题以不高于 50 Hz 发布，并加入默认日志配置。诊断主题不足以分析毫秒级冲击波形，
还需要原始 IMU/削顶记录；不要用诊断发布频率代替飞控控制频率。

## 构建与验证

在仓库根目录：

```bash
make px4_sitl_default -j4
python3 Tools/collision_recovery/run_tests.py
make damiao_dm-fc01_default -j4
```

独立测试脚本依赖本机 g++ 和 GoogleTest。它不启动 PX4、不连接飞控，
检测/DOB 单元测试启用 ASan/UBSan；EKF 集成测试链接实际 SITL EKF 静态库。
原生测试入口也已登记新测试，可在依赖完整时运行对应测试目标。

验证结果与未完成事项见同目录 `validation.md`。
